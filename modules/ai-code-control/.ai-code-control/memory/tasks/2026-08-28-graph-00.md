# GRAPH-00 - query audit and hybrid graph architecture

Status: implemented and validated locally on 2026-08-28.

## Outcome

- A measured inventory covers 25 real query shapes: 10 memory FTS, 10 code graph,
  and 5 trace graph questions.
- Existing FTS and code queries answer 20/25 cases with verifiable source locations,
  but only 14/25 are direct complete answers. All five why/current/evidence trace
  questions are explicitly unsupported at baseline.
- Supported local queries average 177 ms. FTS output averages about 346 tokens; code
  graph output averages about 1,064 tokens. Large class substring searches produced
  37 matches and more than 3,000 tokens, identifying response shaping as a real cost.
- The routing policy sends text discovery to FTS, symbols and blast radius to the code
  graph, authoritative why/current/evidence questions to the trace graph, and human
  exploration to Obsidian.
- Every accepted trace edge type has at least two concrete use cases. Automatic
  `caused` is excluded.
- ADR-0011 accepts an existing-SQLite hybrid design with separate temporal trace tables,
  stable canonical identities, T0/T1/T2 trust tiers, provenance, and fail-closed routing.
- Obsidian remains a batch projection and is never read for authorization or enforcement.

inside its observed uncertainty interval. No parallel Codex sessions were detected.
