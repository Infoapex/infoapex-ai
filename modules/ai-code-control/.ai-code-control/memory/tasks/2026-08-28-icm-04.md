# ICM-04 - semantic snapshots and incremental invalidation

Status: implemented and validated locally on 2026-08-28.

## Outcome

- `task-input-snapshot` v1.1 binds dependency commits to `contextDigest`,
  `contextCompilerVersion`, canonical contract hashes, relevant quality-gate config,
  scope/routing policy, and selected toolchain config.
- Context packages supply selected source hashes in observe and enforce modes. Without
  a package, only exact declared required-input files may contribute contract or
  toolchain hashes.
- Quality-gate hashing includes only gates executed by the task, including global
  gates; changing an unrelated gate does not cause false invalidation.
- The incremental planner emits machine-readable direct invalidation reasons, reusable
  task IDs, and descendants pending a dependency output change.
- Source ordering, run metadata, package identity, timestamps, checkout paths, and
  unselected files do not trigger reexecution.
- The production CLI detects semantic drift against stored task snapshots and fails
  closed with `SEMANTIC_INPUT_DRIFT_REQUIRES_GRAPH_REVISION`; it never reopens a frozen
  terminal run in place.
- Existing descendant invalidation remains commit-driven: descendants become stale
  only after a reexecuted dependency produces a different verified commit.

## Measurement

The preregistered range was 2.5M / 3.5M / 4.5M reported tokens. Actual usage was
5,950,368 tokens, 70.01% above the median and outside the range (RED). Unlike ICM-03,
the usage mapping is comparable: the same session and rate-limit window moved by 22
percentage points, yielding 270,471 tokens per percentage point. No parallel Codex
sessions were detected.

Across the two clean usage samples (ICM-02 and ICM-04), the median observed rate is
241,203 tokens per percentage point. The plan still requires at least three clean
samples before recalibrating future estimates.

## Residual boundary

The stage provides deterministic planning and fail-closed drift detection. Carrying
reusable commits into a new terminal graph revision remains part of graph-revision
orchestration; frozen runs and authorizations are intentionally never mutated in place.
